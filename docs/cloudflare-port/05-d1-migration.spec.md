# 05 — D1 Migration

Moving EdApex from MariaDB 11.8.9 (remote snapshot) to D1, creating the 2026/2027 session as a fresh slate, and carrying the roster forward. Companion spec: [06 — Archive and retrieval](./06-archive-and-retrieval.spec.md).

---

## 1. Source of truth

| | |
|---|---|
| Source | `edapexdb.sql` — 86 MB Adminer dump of the **remote** database, MariaDB 11.8.9 |
| Tables | 316 defined, **218 populated** (98 empty) |
| Ported subset | **62** SMS tables (49 cataloged + 13 FK closure) |
| Migrated volume | 74.0 MB (marks and results dominate) |
| Local database | Development only — fees empty, roster partially seeded; **not** a migration source |

Never migrate from the live database. The dump is immutable, checksummed, and reproducible.

`edapexdb.sql` is gitignored (`/*.sql`) because it contains student, parent, and user records.

## 4. Transform rules

| Rule | Detail |
|---|---|
| **Canonical academic year** | `academic_id` is authoritative; `session_id` is dropped from `sm_students` and `student_records` after reporting disagreements. Never derive from the DDL default — 752 students carry `academic_id = 1` by default, not by fact |
| **Placement** | `sm_students.class_id/section_id` backfilled from the default `student_records` row (870 were NULL) |
| **Booleans** | `tinyint` 0/1 → `INTEGER` 0/1 |
| **Timestamps** | `INTEGER` unix seconds (UTC) |
| **Calendar dates** | `TEXT` `YYYY-MM-DD` (`starting_date`, `attendance_date`, `starts_on`, `ends_on`) |
| **Decimals** | `REAL` for marks; money in integer minor units |
| **Enums** | `TEXT` + `CHECK` constraint |
| **JSON-ish columns** | `TEXT`, validated at the application boundary |
| **`sm_general_settings`** | 106 columns → 12 active columns + `extras TEXT` (94 legacy fields) |
| **`chat_groups`** | Add the missing primary key; generate ids for existing rows |
| **Passwords** | All 1,566 hashes replaced by the shared SHA-256 claim digest ([04a §2](./04a-auth-cutover.spec.md)) |
| **Categories** | Add `UPPERBASIC` to `sm_student_categories`, to `categoryEnum`, and to `TITLES_BY_CATEGORY` (the CA1/CA2/EXAM columns each category prints) |
| **Orphan FK checks** | Report, never guess: any row whose FK target is missing goes to quarantine |

### 4.1 Term model

`sm_exam_types` keeps its table name (6,026 `exam_setups` rows reference it) but is redefined as a **term**:

| Column | Change |
|---|---|
| `academic_id` | Kept — the canonical year FK; no rename to `academic_year_id` |
| `sequence` | **New** smallint; the ordering source for transcripts |
| `starts_on`, `ends_on` | **New** `TEXT` `YYYY-MM-DD` |
| `status` | **New** `planned` \| `active` \| `closed` |
| `grading` | **New** `TEXT` JSON, absorbing `is_average`, `percentage`, `average_mark`, `percantage` |
| `legacy_suffix` | **New** text (`DEC/2025`), preserved only for reproducing old titles |
| `title` | Stored **without** embedded dates; display is rendered as `name — suffix` |

Constraints: `unique(academic_id, sequence)` and `unique(academic_id, name)`.

Migration of the seven existing rows:

1. Copy `id` unchanged (FKs depend on it).
2. Split the title into `name` (`FIRST TERM`) and `legacy_suffix` (`DEC/2025`).
3. Assign `sequence` by date order within each `academic_id`.
4. Set `status = closed` for academic years 1 and 2; `active` for the term containing today.
5. Populate `starts_on`/`ends_on` from the school's calendar — **required input**; rows without dates are rejected rather than defaulted.

### 4.2 `sm_exams` and assessment components

The three layers are distinct and must not be collapsed:

| Table | Represents | Key |
|---|---|---|
| `sm_exam_types` | **Term** | `academic_id` + `sequence` |
| `sm_exams` | **Term × class × section × subject** configuration (`exam_mark`, `pass_mark`) | unique on the five columns |
| `sm_exam_setups` | **Assessment component** (`exam_title` = CA1 / CA2 / EXAM, `exam_mark`) | FK to `sm_exams` and the term |

Measured: 1,433 `sm_exams` rows, **no duplicate keys**, every row `100 / 70`. Therefore:

- Add `unique(school_id, academic_id, exam_type_id, class_id, section_id, subject_id)`. It costs nothing today and prevents the duplicate-config class of bug.
- **Regenerate** the 2026/27 rows from subject assignments × terms rather than copying — the values are boilerplate and the 2025/26 rows carry class ids from the previous ladder.
- Assessment component titles (`CA1`, `CA2`, `EXAM`) **remain free text** in this port. Normalising them into a lookup table is out of scope.

## 5. Load order

Derived from the FK graph by `scripts/plan-migration-order.mjs`; audit FKs (`created_by`/`updated_by`) excluded. Full table in `.kimchi/docs/migration-order.md`.

| Tier | Contents |
|---|---|
| 0 | `sm_schools` (+ no-FK tables `chat_group_users`, `exam_merit_positions`) |
| 1 | `sm_academic_years`, `sm_exam_types`, `infix_roles`, `sm_base_groups`, `sm_designations`, `sm_human_departments`, `sm_languages`, `languages`, `sm_date_formats` |
| 2 | `users`, classes, sections, subjects, dictionaries, resources, finance config |
| 3 | `sm_staffs`, `sm_parents`, `sm_general_settings`, `sm_exams`, `sm_fees_types`, class-teacher assignments |
| 4 | `sm_students`, `sm_exam_setups`, subject assignments, class teachers, schedules, `chat_groups` |
| 5 | `student_records`, promotions, attendance, ratings, remarks, fee assignments |
| 6 | `sm_mark_stores`, `sm_result_stores`, `sm_fees_payments` |

Mechanics:

- `PRAGMA defer_foreign_keys = on;` at the top of each import file — D1 enforces FKs unconditionally and cannot disable them.
- `wrangler d1 execute <db> --remote --file=<file>.sql` uses the import API (5 GiB limit, R2-backed).
- Split files by tier, chain with `&&`, make each idempotent (`INSERT OR REPLACE`).
- Preserve original numeric ids; after load set `sqlite_sequence` so new inserts do not collide.

## 6. Bootstrap: fresh session as a slate

```http
POST /api/v1/admin/sessions/bootstrap
{
  "newSession": { "id": 5, "year": "2026", "title": "2026/2027",
                  "startsOn": "2026-09-14", "endsOn": "2027-07-30" },
  "copyFromSessionId": 4,
  "terms": [
    { "sequence": 1, "name": "FIRST TERM", "startsOn": "2026-09-14", "endsOn": "2026-12-11" }
  ],
  "classes": {
    "copyFromSource": true,
    "add": [
      { "name": "UPPER BASIC 1", "stage": "UPPER_BASIC", "sortOrder": 23 },
      { "name": "UPPER BASIC 2", "stage": "UPPER_BASIC", "sortOrder": 24 },
      { "name": "UPPER BASIC 3", "stage": "UPPER_BASIC", "sortOrder": 25 }
    ]
  },
  "copy": ["sections","classSections","subjects","subjectAssignments",
           "classTeachers","routines","gradeBands","studentCategories","feeStructures"],
  "activate": true,
  "dryRun": true
}
→ 202 { "jobId": "bs_…" }
```

`GET /api/v1/admin/sessions/bootstrap/:jobId` reports per-step status plus a readiness summary:

```json
{
  "status": "completed",
  "steps": [
    { "name": "academicYear", "created": 1 },
    { "name": "terms", "created": 1 },
    { "name": "classes", "created": 14, "notes": "11 copied, 3 new" },
    { "name": "subjectAssignments", "copied": 463 },
    { "name": "gradeBands", "created": 7 }
  ],
  "readiness": { "classesWithoutAssignments": 0, "teachersWithoutClasses": 0 }
}
```

**Fresh-slate guarantee:** creates configuration only. Zero transactional rows — no `student_records`, marks, results, attendance, homework, payments, or chat groups.

**Preconditions:**

- Integrity gate green (§3) unless `force: true` with a written reason (audited).
- Target year contains no `student_records` or marks unless `allowNonEmpty: true`.
- Idempotent: `(school_id, year)` unique; each step upserts and a failed run resumes.
- `dryRun: true` returns planned counts without writing.

**Terms are optional in bootstrap.** `terms: []` or omitting the field creates the session with **zero terms** — a valid fresh slate. If terms are provided they must start at `sequence: 1` and be contiguous; a single term must be the first term, otherwise the request is rejected with `409 TERM_SEQUENCE_GAP`. Term dates are mandatory when a term is supplied: missing, inverted, or overlapping dates are rejected, never defaulted.

### 6.2 Terms endpoint (independent of bootstrap)

Terms can be created or updated after bootstrap, which is how terms 2 and 3 will be added once the school publishes their calendars.

```http
POST /api/v1/admin/sessions/:id/terms
{ "terms": [ { "sequence": 1, "name": "FIRST TERM",
               "startsOn": "2026-09-14", "endsOn": "2026-12-11" } ],
  "dryRun": false }
```

Rules:

- Create-or-update keyed on `(academic_id, sequence)`.
- **Sequential only:** sequence 1 is always allowed; sequence *n* is accepted only when *n−1* already exists. Attempting the second term before the first returns `409 TERM_SEQUENCE_GAP` with the missing sequence.
- Dates required, `startsOn < endsOn`, and no overlap with another term in the same year.
- Returns the full term list for the year after the write.

**First term calendar — Lighthouse Leading Academy, Makurdi, 2026/2027** ([calendar.jpeg](./assets/calendar.jpeg)):

| Milestone | Dates |
|---|---|
| Term | **2026-09-14 → 2026-12-11** (13 weeks) |
| CA 1 | Week 5: 2026-10-12 → 2026-10-16 |
| Open Day | 2026-10-28 |
| Mid-term break | 2026-10-29 → 2026-10-30 |
| Examinations | Week 11: 2026-11-23 → 2026-11-27 |
| Compilation | Week 13: 2026-12-07 → 2026-12-11 |

Public holidays are observed as declared; the calendar note states this explicitly. Terms 2 and 3 remain unscheduled until their calendars are published — which is exactly why bootstrap accepts a session with only the first term.

### 6.1 Class staging and copy semantics

`sm_classes` becomes a ladder rather than a flat list:

| Column | Rule |
|---|---|
| `stage` | `EARLY_YEARS`, `LOWER_BASIC`, `MIDDLE_BASIC`, `UPPER_BASIC` |
| `sort_order` | Ascending progression; drives batch order and display |
| `next_class_id` | Points at the **next year's** class row for that level |

Seeded progression for 2026/27:

```text
CRECHE → NURSERY 1 → NURSERY 2 → GRADE K → LOWER BASIC 1
       → LOWER BASIC 2 → LOWER BASIC 3 → MIDDLE BASIC 4
       → MIDDLE BASIC 5 → MIDDLE BASIC 6 → UPPER BASIC 1
       → UPPER BASIC 2 → UPPER BASIC 3 → NULL (graduate)

DAYCARE → DAYCARE (next year's row; not part of the ladder)
GRADE 1–6 → NULL (historical only)
```

Copy semantics reuse the existing `copy_with_academic_year` concept: source year 4 already declares `App\SmClass, App\SmSection, App\SmSubject, App\SmExamType` as the entities to carry into a new session. The bootstrap does exactly that, then adds the three UPPER BASIC rows.

**Fees:** measured empty on the remote (`sm_fees_assigns` and `sm_fees_payments` have no rows). Structures are therefore **seeded fresh**, not migrated, and only when the school enables finance for 2026/27.

## 7. Promotion — class by class

Runs after bootstrap. Descending class order so a destination is never populated before its own cohort moves. Per-class batches, resumable, idempotent.

| Batch | From | To | Students |
|---|---|---|---|
| 1 | MIDDLE BASIC 6 (22) | UPPER BASIC 1 (new) | 18 |
| 2 | MIDDLE BASIC 5 (21) | MIDDLE BASIC 6 (22) | 47 |
| 3 | MIDDLE BASIC 4 (20) | MIDDLE BASIC 5 (21) | 65 |
| 4 | LOWER BASIC 3 (19) | MIDDLE BASIC 4 (20) | 62 |
| 5 | LOWER BASIC 2 (18) | LOWER BASIC 3 (19) | 78 |
| 6 | LOWER BASIC 1 (17) | LOWER BASIC 2 (18) | 70 |
| 7 | GRADE K (15) | LOWER BASIC 1 (17) | 88 |
| 8 | NURSERY 2 (14) | GRADE K (15) | 81 |
| 9 | NURSERY 1 (13) | NURSERY 2 (14) | 92 |
| 10 | CRECHE (12) | NURSERY 1 (13) | 53 |
| — | DAYCARE (16) | **stays in DAYCARE** (new year row) | 24 |

Totals reconcile: 654 promoted + 24 staying + 3 unplaced = **681 current records**.

Rules:

- Source of truth for placement is `student_records` (`is_default = 1`, `academic_id = 4`) — **not** `sm_students.class_id`.
- Each batch writes `promotion_batches` and `promotion_outcomes`, creates the 2026/27 `student_records` row, updates `sm_students.academic_id/class_id/section_id`, and sets `is_default`.
- `next_class_id` drives the mapping; `UPPER BASIC 3` has `NULL` and produces `graduated`.
- GRADE 1–6 historical classes keep `next_class_id = NULL` (never promoted).

### Quarantine report

Two categories, one print-ready document grouped by class: `NO_CURRENT_RECORD` (219) and `UNPLACED` (3). Columns: student name, admission number, guardian name, guardian phone, reason. Endpoints: `GET …/promotion/quarantine.pdf` and `.csv`. Generating it changes nothing.

## 8. Verification and cutover

**Pre-cutover**

1. Row counts per table: dump vs D1; any variance explained.
2. Checksums per archived object; manifest count equals exported count.
3. `PRAGMA foreign_key_check` returns zero rows.
4. Index count per table equals the recovered inventory (222).
5. Business invariants: every student has one current record; every class-section has a subject assignment; every term has dates; 7 grade bands exist for year 5.
6. Readiness test: teacher → classes → roster → term → marks entry → report card renders with a grade.

**Cutover**

1. Freeze writes; final delta export.
2. Run the promotion batches; generate the quarantine report.
3. Switch traffic to Hono; enable `/claim`.
4. Monitor claim metrics, 5xx rate, and query budget for 24 h.

**Rollback:** MySQL remains authoritative and read-only until every pre-cutover check passes. Trigger: any FK violation, any unexplained count variance above 0.1%, or result totals differing from the spot-check set.
