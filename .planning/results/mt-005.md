## Deviations from the microtask spec
The spec instructed the config to use `poolOptions.forks.singleFork: true`. Vitest 4 removed `test.poolOptions` entirely (per the official migration guide) — pool-specific options are now top-level, and `singleFork` semantics are expressed as `maxWorkers: 1, isolate: false`. I used the modernized form so vitest doesn't emit a `DEPRECATED` warning. The serialization behavior is preserved (single worker, no module isolation, sequential within the file via `sequence.concurrent: false`).

All other constraints were met verbatim:
- `include: ['tests/**/*.integration.test.ts']`
- `testTimeout: 60000`
- `sequence.concurrent: false`
- `$lib` alias mirrors `vitest.config.ts` exactly
- No new dependencies added
- Existing `vitest.config.ts` and `test` script untouched
