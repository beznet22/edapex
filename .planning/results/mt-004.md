## Exports

### `types.ts`
- `SchoolInsert`, `AcademicYearInsert`, `ExamTypeInsert`, `ClassInsert`, `SectionInsert`, `ClassSectionInsert`, `UserInsert`, `StaffInsert`, `StudentInsert`, `StudentRecordInsert`, `ParentInsert` — derived from `typeof table.$inferInsert`

Each builder returns `Omit<$inferInsert, "id">` with sensible defaults for required fields and `...overrides` spread last so callers can override any column.

## Deviations from Spec

1. **Spec named `sm_users` and `sm_student_records`, but the actual exports in `src/lib/server/db/sms-schema.ts` are `users` and `studentRecords`.** The microtask author abbreviated two of the eleven tables. I used the actual exports; downstream consumers (mt-001 `withTenantFixture`) will already know to import from the same schema module, so this is the correct binding.
2. **`pnpm run lint` does not exist** in `package.json` (no ESLint/Prettier config in repo). The spec's DoD step referencing lint was unfulfillable in this codebase; I verified TypeScript strictness via `pnpm run check` (svelte-check) and `tsc --noEmit`, both pass with **0 errors**. The 25 pre-existing warnings are in unrelated Svelte files outside the scope of this microtask.
