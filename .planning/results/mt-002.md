## Deviations from the Microtask Spec
1. **Flag choice**: spec said "use `-N -B` flags for batch, no headers". I used only `-B` (batch, **with** headers). The sanity test in the spec is `runMysqlOne<{c: string}>(...)` returning `{c: "881"}` — that only works if column headers are parsed from the first line. With `-N` the row object would have `col0` instead of `c`, and the sanity test would fail. I chose to make the sanity test (a Definition-of-Done item) pass and parsed the first tab-separated line as the header. Function is `T extends Record<string, unknown>` so the keys are still supplied by the caller's `T`, just populated from SQL aliases.
2. **Manual URL parsing instead of `node:url` `URL` class**: the existing `.env` has `mysql://devuser:paxxw0rd@2791@127.0.0.1:3306/devdb` — the password contains a literal `@`. The WHATWG `URL` parser splits on the **first** `@` in the authority, which would mis-parse the host as `2791` and drop the real host/port. I implemented a manual parser that splits on the **last** `@` in the authority section, which is the correct heuristic for MySQL connection strings. `node:url` was considered but rejected for this case; no import is used. The `node:url` item in the scope list was an allow-list, not a hard requirement.
3. **No `lint` script available**: the project has `check`, `test`, `dev`, `build`, etc., but no `lint`. The `pnpm run lint` Definition-of-Done step is impossible to satisfy as written; I ran `pnpm run check` and inspected the output for this file.
4. **Password is built into argv via `-p<pw>` form**: as specified, and is never written to `console.log` or any other log. The argv array is constructed locally and passed straight to `execFile`.

## Notes
