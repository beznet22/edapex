# mt-003 — canConnectDb.ts

## Summary
Implemented a probe helper that tests live MySQL connectivity for the
integration test suite. Used by `describe.skipIf(...)` so suites skip
gracefully when the DB is unreachable (e.g., CI without MySQL).

## Files Written
- `tests/lib/server/mastra/integration-helpers/canConnectDb.ts` (63 LOC)

## Behavior
- Exports `canConnectDb(): Promise<boolean>`.
- Reads `DATABASE_URL` from `$env/dynamic/private` (same source as
  `src/lib/server/db/index.ts`).
- Opens a fresh `mysql2/promise` connection with a 3 s `connectTimeout`,
  runs `SELECT 1`, returns `true` on success, `false` on any failure.
- Caches the result in a module-level `cachedResult`; in-flight calls share
  the same promise so concurrent probes never hit the DB twice.
- All errors are caught and converted to `false`; never throws.
- On failure (DB unreachable, missing URL, or query error), `console.warn`s
  once with the sanitized message `"DB unreachable for integration tests;
  skipping."`. No logging on success.

## Sanity Test Results
Wrote a temporary vitest file (`tests/.tmp/sanity.test.ts`, since removed)
covering the three required cases:

| Case | Result | Elapsed |
|------|--------|---------|
| Live `devdb` reachable (real `DATABASE_URL`) | `true` | < 3 s |
| Second call returns cached result | `true` | < 10 ms |
| `DATABASE_URL` pointed at `127.0.0.1:1` (refused) | `false`, no throw | < 3.5 s |

All 3 vitest cases passed.

## Deviations from Spec
1. **Lint step skipped.** Spec says "File passes `pnpm run lint path/to/file.ts`",
   but the project has no `lint` script in `package.json` and no ESLint /
   Prettier config files. Ran `pnpm run check` (which is the project's
   actual verification command) instead. The file is a single small
   self-contained module and conforms to the surrounding code style.
2. **Default URL path is `devdb`** (per `.env`); sanity test used the
   real credentials, not a placeholder. This was needed because the
   `mysql2` driver rejects on auth failure, so a placeholder would have
   masked the real connect-success path.
3. **Restructured probe body** (final code is 63 LOC vs. ~60 estimated)
   to hoist `connection` into a `Connection | null` variable so the
   `finally { connection.end() }` block can safely no-op when
   `createConnection` itself throws (e.g., `ECONNREFUSED`). Otherwise the
   TDZ on `const connection` would re-throw from the `finally` and
   bypass the catch — verified by the unreachable-host sanity test.

## Notes
- Uses `mysql2/promise` directly (not Drizzle), per spec.
- Does not mutate any global Drizzle pool, so it is safe to call
  independently of `getDatabase()` from `src/lib/server/db/index.ts`.
- Caching means CI processes that import the module and then lose DB
  connectivity mid-run will keep returning the original cached result.
  This is intentional: it prevents `describe.skipIf` from flipping state
  after the suite has already started.
